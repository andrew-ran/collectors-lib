### Added
- Laravel 13 backend and React 19 + TypeScript + Vite frontend scaffolded (`src/backend`, `src/frontend`).
- Pest installed for backend testing.
- Migrations for all tables in `docs/DATABASE_SCHEMA.md`.
- Seeders for the two default collections and a placeholder platform list (real IGDB sync pending API access).
- `docker-compose.yml` (app, queue, frontend, nginx, db, redis) and backend `Dockerfile`.
- `.env.example` updated for MySQL/Redis service names and IGDB/Screenscraper credential placeholders.
- `/api/health` route for the Phase 0 sanity check.
- Laravel Pint config and Prettier config + scripts for the frontend.
- Eloquent models + enums (`ItemType`, `ScrapeStatus`, `Priority`, etc.) for every table.
- Admin auth via Sanctum tokens: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me` (US-100/101/102).
- `AdminUserSeeder` (reads `ADMIN_EMAIL`/`ADMIN_PASSWORD` from `.env`).
- Item CRUD (`ItemController`): public `GET /api/items`, `GET /api/items/{item}`; auth-gated create/update/delete (US-115/116).
- Rate limiting: general `api` limiter + a stricter `login` limiter (`AppServiceProvider`).
- `IgdbService` (Twitch OAuth + Apicalypse queries) and `ScrapeItemMetadataJob` (franchise/company/genre matching included) — exercised live end-to-end 2026-08-17 (Twitch app credentials obtained, `POST /api/items` with a real `igdb_id` correctly scraped description, release year, franchise, developer/publisher, genres, and raw IGDB payload).
- Frontend auth: axios client with Bearer-token interceptor, zustand auth store (persisted to localStorage), TanStack Query hooks (`useLogin`/`useLogout`/`useCurrentAdmin`), `ProtectedRoute`, `/admin/login` and `/admin` pages, routing via react-router-dom (US-100/101/102, full stack).
- Xdebug installed in the backend `Dockerfile` (dev image only) + `src/backend/docker/xdebug.ini`, for PHPStorm step debugging.
- PHPStorm HTTP Client requests (`requests/collectors-lib.http`, `requests/http-client.env.json`) covering health check, auth login/me/logout, and item CRUD.
- US-110 (admin add-item via IGDB search), full stack: `GET /api/search/igdb` (`IgdbSearchController`, matches/creates local `Platform` rows by `igdb_id` on the fly), `GET /api/collections` (`CollectionController`), and `AdminAddItemPage.tsx` (collection picker, ~400ms debounced search, result list with cover thumbnails, platform-confirm step, US-111 "Scraping...→Ready" status per added item).
- Tailwind CSS v4 (`@tailwindcss/vite` plugin) and Framer Motion added to the frontend per `docs/TECH_STACK.md`, ahead of Phase 2's public SPA work. shadcn/ui is intentionally not bulk-installed -- components get added one at a time via its CLI as Phase 2 screens actually need them.
- Public Item View (US-001/001b/002/003/005/010), now the site's `/` homepage: `CollectionItemViewPage.tsx` shows a collection's items one at a time (cover, title, platform, genres, description, franchise, "available on" platforms, sequel/prequel/remake tags, year), with a collection-switcher dropdown, on-screen/keyboard arrow navigation, and a position indicator. Backed by `GET /api/items?collection_id=&per_page=` (index() now accepts a `per_page` override, capped at 200) and `GET /api/items/{item}` (now also eager-loads `metadata.franchise`). `Item::coverUrl()` accessor added -- resolves an admin-set primary photo, then a locally stored cover, then falls back to hot-linking IGDB's own cover image until `ImageService` exists. Deliberately out of scope for this pass: filters/sort (US-006-009), sequel/prequel tag interactivity (US-011), and the photo slider/lightbox (US-012).
- Filters, sort, URL state, and empty/loading states for the Item View (US-006/006a/007/008/008b/008c/009): Platform/Genre/Series filter tags (grayed out when the current collection has no values for that dimension), a sort dropdown (Newest/Oldest added, A→Z, Z→A -- "added" means `acquired_date`, not `created_at`), a shared `Dropdown`/`DropdownItem` component (extracted from the collection switcher, same 4-row-then-scroll behavior everywhere), item count, and distinct "no items match these filters" (with a Reset action) vs "collection is genuinely empty" states. Selection is stored in the URL (`?collection=&platform=&genre=&franchise=&sort=`) via `useSearchParams`, so a view is bookmarkable/shareable; changing any of them remounts the item browser (via a composed `key`) to reset back to item 1, instead of an effect+setState. Backend: `GET /api/items/filter-options` (scoped to the current collection) and `ItemController::index()` now accepts `platform_id`/`genre_id`/`franchise_id`/`sort`. Wishlist's Most/Least-wanted and Price sort options are deferred until the Wishlist card fields (US-020/021) exist to fetch that data from.
- Wishlist card fields and priority/acquisition badges (US-020/021/022/023): `ItemCard` now shows condition preference, edition note, and estimated price (new/used) for items in a Wishlist-type collection, plus a click-to-expand priority badge (ice cube/orange slime/burning meteor icon over the cover, expanding to a pill with the exact desire score %). Items that started in the Wishlist and have since moved to a regular collection (`wishlist_detail.received === true`) instead show a Gifted/Purchased acquisition badge in the same card position -- a registered gifter's avatar (hover tooltip with their name, click-to-expand pill with the thank-you note), a generic gift-box icon for a gift with no gifter on file, or a wallet+checkmark icon for a self-purchase (both tooltip-only, not interactive). Backend: `WishlistDetail::priority()` is now an appended Eloquent accessor (was a plain, unserialized method) derived from `desire_score`; `ItemController::show()` eager-loads `wishlistDetail.gifter`. Currency display (US-170/171) isn't wired up yet -- prices render as plain numbers. Untested against real acquisition-badge data, since US-151 (mark received) doesn't exist yet to produce it.
- Related-game tag interactivity (US-011): sequel/prequel/remake tags now show a comic-style tooltip on hover ("не в коллекции" if the game isn't owned or wishlisted anywhere, "Wishlisted" if it is), a green checkmark if it's owned, and are clickable when owned/wishlisted -- clicking jumps straight to that game's own card, in its own collection. Backend batch-matches each tag's IGDB id against local items in one query (`ItemController::enrichRelatedGames()`) rather than one query per tag.
  - **Known limitation, by design:** IGDB's API has no direct "sequel"/"prequel" relation between games -- only franchise membership and a release date. "Sequels"/"prequels" are therefore *approximated*: every other game in the same IGDB franchise, split into earlier/later by release date relative to the current game. This also catches spin-offs and side entries from the same franchise, not just direct numbered sequels. Remakes/remasters are exact (IGDB does have those as real fields). Planned to be revisited -- see `docs/tz/TECH_DEBT.md`.
- The Related row is now capped by default to the 2 closest prequels + 2 closest sequels + anything already owned + all remakes, with a "Show more" link revealing the full list -- a long-running franchise's full sequel/prequel list was stretching the card considerably. Still a stopgap, not a real layout fix -- see `docs/tz/TECH_DEBT.md`.

### Fixed
- `Dockerfile` was missing the `redis` PHP extension, breaking anything touching cache/queue/rate-limiting ("Class \"Redis\" not found").
- nginx dotfile-deny rule was blocking Vite's `/node_modules/.vite/deps/...` cache requests (403) — removed, see `docker/nginx.conf`.
- Docker nginx moved from host port 80 → 8080 → 8090. Port 80 is taken by a native Homebrew nginx, and port 8080 turned out to be taken by that same native nginx too (serving other local vhosts, e.g. `Fortis`) — requests to `:8080` were silently answered by it instead of our container. `docker-compose.yml` and `.env`/`.env.example` (`APP_URL`, `FRONTEND_URL`) updated to `collectors-lib.test:8090`.
- `db` service host port moved from 3306 → 3307 (3306 is already used by another local MySQL install). Internal `DB_PORT` in `.env` stays 3306 (container-to-container, unaffected).
- `ScrapeItemMetadataJob` never matched/attached genres (`item_genres` stayed empty despite `igdb_raw.genres` having data) — added `matchGenres()` (mirrors `matchFranchise()`) and `item->genres()->sync(...)`.
- `ScrapeItemMetadataJob` only overwrote `title` when it was empty (`?:`), which never happens since `title` is required at creation — title is now always overwritten with IGDB's name once an item has an `igdb_id`, since IGDB is the authoritative source.
- `IgdbSearchController::matchPlatform()` matched existing platforms by `igdb_id` only, colliding on the unique `slug` constraint against `PlatformSeeder`'s pre-seeded rows (which intentionally have `igdb_id = null`) — e.g. searching a PS4 title 500'd on a duplicate `playstation-4` slug. Now also falls back to matching by slug and backfills `igdb_id` on the existing row instead of trying to insert a duplicate.
- `AdminAddItemPage.tsx` silently swallowed search errors (just stopped showing "Searching..." with no result and no error) — added error display and a "No results." state.
- CI's backend job failed on `cp .env.testing.example .env.testing` -- that file never existed (`.github/workflows/ci.yml` was written during Phase 0 docs, before there was a real test setup to point it at). Added `src/backend/.env.testing.example`, wired to the CI workflow's `mysql` service and `array`/`sync` drivers (no Redis service defined in CI).
- `.github/workflows/ci.yml` bumped `actions/checkout`/`actions/setup-node` v4 → v7 (v4 still runs on the Node 20 runtime GitHub is removing from Actions runners on 2026-09-16) and the frontend job's `node-version` 20 → 22, matching the Node version used everywhere else in the project (Docker, local dev).
- `ScrapeItemMetadataJob` populated the "sequels" field from IGDB's `similar_games` (a fuzzy similarity match, not real sequel data) and never populated "prequels" at all. Both are now derived from same-franchise games split by release date -- see the Related-game tag entry above for the approximation this introduces instead.
